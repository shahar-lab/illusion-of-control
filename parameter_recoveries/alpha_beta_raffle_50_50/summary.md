# Parameter Recovery: alpha_beta (raffle, fixed 50/50 reward)

## Goal
Verify that the `alpha_beta` Stan model can recover its two free parameters
(`alpha`, `beta`) from synthetic data generated by the matching simulator, on the
2-arm forced-choice raffle task with fixed 50/50 reward probabilities for every arm.

## Model
Hierarchical Rescorla-Wagner Q-learning model over a 2-alternative forced-choice
raffle: each trial offers exactly 2 of `n_arms` cards (left/right), and choice is
modeled as a binary logistic decision on the Q-value difference between the two
offered cards (`bernoulli_logit(Q_right - Q_left)`), rather than a general softmax
over an arbitrary-size offered set. Only the chosen card's Q-value updates via a
standard delta rule; Q-values reset to 0.5 at the start of each block.

Two free parameters:
- `alpha`: learning rate, bounded [0, 1] via inv_logit transform (hierarchical
  inv_logit-normal)
- `beta`: inverse temperature, **unconstrained** (mu_beta + sigma_beta * raw, no
  exp transform) — can go negative, unlike `classic_qval_raffle`'s log-normal `beta_rl`

## Simulation setup
- n_subjects = 200, n_arms = 4, n_raffle = 2, n_trials = 200, n_blocks = 1
- Reward schedule: fixed 50/50 win probability for all arms/trials (despite the
  `01_set_task_parameters.R` / `02_generate_random_walk.R` naming and the
  `rw_step_sd` config value, `expvalues` is a constant 0.5 matrix — there is no
  actual random walk in this pipeline)
- True population generators: mu_alpha = 0, sigma_alpha = 1.25; mu_beta = 3.5,
  sigma_beta = 1.25

## Pipeline (via main.R)
1. `01_set_task_parameters.R` — task config
2. `02_generate_random_walk.R` — fixed 50/50 `expvalues` matrix
3. `03_visualize_random_walk.R` — sanity plot
4. `04_set_agent_population_parameters.R` — population generators
5. `05_generate_agents_parameters.R` — per-subject true parameters
6. `06_generate_parameters_visualization.R` — sanity-check simulated parameter distributions
7. `07_set_model.R` — model name config
8. `08_generate_behavior.R` — simulate 200 agents
9. `09_fit_model.R` — fit hierarchical Stan model (4 chains, 2000 warmup, 2000 sampling)
10. `10_recovery_visualization.R` — true vs. recovered scatter + population posteriors

Note: unlike `classic_qval_raffle_param_recovery`, this pipeline has no separate
`diagnostics.R` step and `09_fit_model.R` only saves draws for `alpha_sbj`,
`beta_sbj`, `mu_alpha`, `mu_beta` — not `sigma_alpha`/`sigma_beta`. Convergence for
the sigma parameters was not checked on this run.

## Results (run 2026-08-26)

- **Runtime:** ~11 min (653s total MCMC across 4 parallel chains; ~645s mean
  per-chain)
- **Divergent transitions:** 0
- **Max treedepth hits:** 0
- **Rhat / ESS** (checked for `mu_alpha`, `mu_beta` only — `sigma_alpha`/`sigma_beta`
  draws were not retained by `fit_stan.R`, see note above):
  - `mu_alpha`: rhat = 1.00, ess_bulk = 1628, ess_tail = 2757
  - `mu_beta`: rhat = 1.00, ess_bulk = 2905, ess_tail = 4829
- **Pearson r (subject-level recovery):**
  - alpha: r = 0.92
  - beta: r = 0.82
- **Population posteriors:** both `mu_alpha` and `mu_beta` posteriors tightly
  bracket their true generating values (0 and 3.5 respectively); posterior median
  and true value are visually indistinguishable in the population plots.

### Notes
- Convergence (0 divergences, Rhat = 1.00, large ESS) is clean for both
  population means checked. Combined with strong subject-level recovery, `alpha`
  and `beta` are identifiable under this design.
- The beta scatter (panel D) shows classic hierarchical shrinkage: recovered
  values are pulled toward the population mean, so high true beta values are
  slightly under-recovered and low ones over-recovered relative to the identity
  line. This is expected model behavior, not a convergence problem.
- Two pipeline gaps found and fixed/noted while running this for the first time:
  - `08_generate_behavior.R` sourced the model file with a lowercase `.r`
    extension instead of `.R`, which fails on case-sensitive filesystems (fixed).
  - `fit_stan.R` does not save `sigma_alpha`/`sigma_beta` draws or call
    `fit$summary()` before `save_object()`, so those group-level SDs' convergence
    can't be checked after the fact from the saved artifacts. Worth extending
    `fit_stan.R` to also save `sigma_alpha`/`sigma_beta` draws in a future run.
